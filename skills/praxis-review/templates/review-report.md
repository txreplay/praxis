# Code Review Report Template

Default template. A project can replace it with `praxis.json › review.report_template`.

## Review Summary

```markdown
## Review Complete

### Source: [mode/spec/commit/feature]
### Scope: [back/front/both]
### Agents used: [list]
### Context: [project guide ✓/✗ · ticket ✓/✗ · spec/mock ✓/✗]

### Files Reviewed
- [count] backend files ([domain keys])
- [count] frontend files ([domain keys])
- [count] other (config/docs/generated)

### Prior review feedback
- Bot findings extended: [ids, or "none"]
- Unresolved human blocking comments from a previous round: [list or "none"]

### Issues Found
- [count] Critical · [count] Important · [count] Minor · [count] Open questions

### Falsifiability
- [count] assertions proven falsifiable (mutation run + reverted)
- [count] traced only, not run — [why]
- [count] assertions that survived the mutation → Critical

### Fixes Applied
- [list or "None requested"]

### Passes
- Simplify: [n changes / skipped] · Comment hygiene: [n removed, n kept, n flagged / skipped] · Factorization: [n / skipped]

### Final Scores
- Backend: X/100 · Frontend: X/100 · Global: X/100

### Recommendations
- [follow-up actions]
```

## Quality Score Summary

```markdown
## Global Quality Score: X/100

### <Domain> Score: X/100
| Criterion (from the domain checklist) | Score | Notes |
|---|---|---|

**Formula:** Σ(domain score × domain files) / total files (generated + config/docs excluded)
```

## Recommended Fixes

```markdown
### Critical (must fix)
1. **[Issue Title]**
   - File: `path/to/file:123`
   - Problem: [what is wrong]
   - Evidence: [traced chain `file:line` → `file:line`, or command run + its output]
   - Fix: [specific steps]
   - Risk if not fixed: [impact]

### Important (should fix)
### Nice-to-have
### Open questions (could not reproduce — questions, not corrections)
1. **[Suspicion]** — `path:line` · What I tried · What would settle it
```

## Verification Checklist

```markdown
## Verification

Affected projects: [from the project's affected command]

- [ ] Targeted typecheck / lint / test pass on each affected project
- [ ] Generated artefacts regenerated by their generator, never hand-edited
- [ ] Formatting check passes on the change range
- [ ] No secret / production PII introduced
- [ ] Migrations safe for a rolling deploy; indexes cover new filters (if applicable)
- [ ] CI read: every target's real status and duration; nothing "passed" in under a second unexplained
- [ ] Failing checks reproduced on `origin/main` before being attributed to this diff
- [ ] No `--no-verify` without asking the user
- [ ] Every mutation from §2.7 reverted (`git status` clean)
- [ ] Manual test cases: [list]
```
